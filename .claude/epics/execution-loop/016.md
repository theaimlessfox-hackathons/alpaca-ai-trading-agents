# Subissue 016: Atomic close_structure

## Description

Close a credit spread with **one** multi-leg closing order. Independent per-leg closes are forbidden: one filled short and one unfilled long is a naked option.

If the schema cannot express an atomic multi-leg close, **fail closed**. Do not submit. Mark the structure `NEEDS_REVIEW` and require a human.

Same idempotency as entries: two halt/TP/SL/STOP/recovery triggers must not submit two closes.

## Acceptance Criteria

- [ ] `close_structure(id)` is allowed only when structure is OPEN; it sets structure `CLOSING` and inserts a **new** close order (`role=close`, OrderStatus INTENT→…)
- [ ] `close_structure(id)` builds exactly one multi-leg close payload (both legs, `order_class=mleg` or dumped equivalent)
- [ ] No code path submits a single-leg close for an open spread
- [ ] Unit test: close payload contains both legs; a one-leg close helper does not exist
- [ ] If atomic close cannot be built, function returns `FailClosed` and writes `NEEDS_REVIEW` — zero broker calls
- [ ] Deterministic `client_order_id` derived from `structure_id + "close"`
- [ ] Persist close intent **before** the network call
- [ ] If DB already has a WORKING/CLOSING/CLOSED close for that structure, return that row and do not submit
- [ ] If Alpaca already has a working order with that `client_order_id`, record it and do not duplicate
- [ ] Per-structure transition lock: concurrent `close_structure` calls serialize; second caller is a no-op
- [ ] Ambiguous timeout is `NEEDS_REVIEW`, not a retry
- [ ] Does not call the LLM
