# Subissue 014: Partial-fill handling

## Description

A partial fill is an **order** state. The **structure** is OPEN for filled quantity even if the leftover working qty is later canceled.

Example: entry qty 2, fill 1, then cancel remainder.

- Order: `CANCELED` (or `PARTIALLY_FILLED` then `CANCELED`), `filled_qty=1`
- Structure: `OPEN` with open qty 1 — **not** canceled, **not** closed

A close order that is rejected or partially filled does **not** set the structure to CLOSED.

## Acceptance Criteria

- [ ] Entry qty 2, filled 1: order=`PARTIALLY_FILLED`, structure=`OPEN`, open_qty=1
- [ ] Then cancel remainder: order=`CANCELED`, filled_qty=1, structure still `OPEN` with open_qty=1
- [ ] pytest fixture encodes that pair of statuses (must fail if someone writes structure=`CANCELED`)
- [ ] Max-loss / risk uses filled (open) qty, not the original order qty
- [ ] Close order `REJECTED` leaves structure `OPEN` (or `CLOSING` only while a working close exists)
- [ ] Close order `PARTIALLY_FILLED` leaves structure `CLOSING` until remaining legs are resolved atomically or `NEEDS_REVIEW` — never silent CLOSED
