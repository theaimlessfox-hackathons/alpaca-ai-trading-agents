# Subissue 009: Split OrderStatus and StructureStatus

## Description

Orders and structures are different objects. An order can be CANCELED while the structure is still OPEN on the filled qty. A close order can be REJECTED or PARTIALLY_FILLED while the structure stays OPEN or CLOSING.

Define both enums in foundation so the ledger schema does not collapse them.

## Acceptance Criteria

- [x] `config/states.py` exports `OrderStatus` and `StructureStatus` (enum or Literal)
- [x] `OrderStatus`: INTENT, SUBMITTING, WORKING, PARTIALLY_FILLED, FILLED, CANCELED, REJECTED, EXPIRED, NEEDS_REVIEW
- [x] `StructureStatus`: PENDING_ENTRY, OPEN, CLOSING, CLOSED, NEEDS_REVIEW
- [x] The two types do not share CLOSING or CLOSED with order terminal names except by coincidence on structure only
- [x] `OrderStatus.CANCELED` is legal; there is no `StructureStatus.CANCELED`
- [x] Illegal combo helper or comment: order CANCELED + filled_qty > 0 ⇒ structure OPEN (not canceled)
- [x] Unit test: the two enums are disjoint conceptually (canceling an order does not imply a structure status change)
